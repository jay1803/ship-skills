# Skill Backlog Mode

Use when stable scope concerns a reusable Skill, playbook, or workflow capture.
Identify its trigger, inputs, output, repeatable non-obvious decisions, and
existing overlapping Skills before proposing a new one. A simple task may need
no Skill; prefer updating the existing owner when its boundary matches.

Each ticket delivers a usable, validated Skill or an independently useful
migration/capability. Capture, entrypoint authoring, resources, tests, and
validation belong inside that ticket; do not create one ticket per lifecycle
phase. Split only when outcomes can be independently accepted or deferred.

Name the target Skill, source evidence, needed resources, acceptance,
validation, dependencies, and migration/rollback implications when relevant.
Do not require scripts, assets, examples, or aliases without a concrete use.
Return the draft tree; the authorized project controller owns live writes.
