# Project Kickoff

Translate an approved direction into an execution agreement and project entry
point. Read the [document contract](../project/references/document-contract.md).

## Establish the approved boundary

Read the proposal revision and approval evidence, including approver, conditions,
scope, resources and dates where known. An explicit user decision can be recorded
with attribution; a document review pass cannot substitute for that decision.
If approval is absent, prepare a clearly labeled kickoff draft if useful, show
what confirmation is missing and leave the lifecycle before approved kickoff.
Do not invent resource commitments or silently widen the approved scope.

Check whether an Entry Page already exists from supplied links or the requested
destination. Reuse it. When creating one, use the
[Entry Page template](assets/entry-page-template.md). Small projects can include
kickoff content on the same page; create a separate kickoff document only when
it helps the audience or is requested.

## Align execution

Make the project's purpose, scope/non-goals, success criteria, stakeholders,
responsibilities, workstreams, milestones, resource commitments, dependencies,
risks and decision owners understandable. Use proposed/TBC for unconfirmed
owners, dates or resources. Identify unresolved dependencies that prevent an
executable agreement; useful drafting can continue while those remain pending.

Include discussion topics and decisions needed at kickoff, then capture actual
outcomes when provided. A prepared agenda is not a meeting held; attendance is
not agreement. Record confirmed agreements and unresolved objections separately.

Populate the Entry Page with verified links to the proposal, approval, working
docs, execution systems, channel and meeting notes where available. Missing
Slack/Notion resources are gaps, not a reason to invent them or block all local
work. Creating resources or sending invitations is a separate authorized action.

## Review and completion

Use [proj-review](../proj-review/SKILL.md) for a reviewed kickoff deliverable.
Preserve the approved baseline and decision record, initialize current plan and
history, and record the next action. Return the verified page/draft plus open
commitments and decisions. Distinguish kickoff prepared, agreements confirmed
and execution started using evidence; do not automatically activate tracker
issues or dispatch Product/Develop work.
